# 收入预估报告响应式与视觉升级设计

- 日期：2026-08-04
- 状态：已按用户“全部采用推荐方案、一口气完成”的明确授权确认
- 适用范围：收入预估全省页、17 个地市页、现有公开报告、私有报告和未来由 `income-forecast-2-0` 生成的报告

## 1. 背景与问题

收入预估报告当前以桌面大屏为主要布局目标。实机浏览器检查显示，768px 平板宽度没有整页横向溢出，但 360px 手机宽度存在明显跑版：全省页文档宽度达到 556px，地市页达到 609px。根因不是单张表格，而是 `.content`、卡片、图表和地图的最小内容宽度共同把页面撑大；现有 640px 媒体查询只把部分网格改成单列，没有建立“页面容器可收缩、宽表仅在自身滚动”的完整约束。

视觉上，现有深蓝数据大屏语言具备基础辨识度，但在小屏上层级过密、阴影和面板重量接近、首屏信息焦点不够明确。升级目标是把它变成克制、专业、可触控的“响应式报告工作台”，而不是另做一套移动版页面。

## 2. 成功标准

1. 全省页和任一地市页在 360、390、768、1024、1440px 宽度下均不产生整页横向滚动；只有标记为 `.table-scroll` 的宽表允许局部横向滚动。
2. 手机端保持全省地图、KPI、驱动因素、业务表、地市排名、日期选择、主题切换、打印和 17 地市跳转等原功能，不以隐藏关键数据换取适配。
3. 手机端正文不小于 13px，主要控件最小触控尺寸 44px；聚焦状态、键盘导航、浅色/深色主题、打印和 `prefers-reduced-motion` 均可用。
4. 平板在单列和桌面宽屏之间形成稳定的两区布局，不出现“把桌面整体缩小”的小字效果。
5. 新视觉仍是湖北电信经营分析报告：深海军蓝底、青蓝数据色、绿色增长、红色风险、琥珀提示；通过层级、留白、细边框和局部光感提升质感，不使用过量霓虹、玻璃或装饰动画。
6. 模板是唯一权威来源。现有报告可由发布管线同步升级，未来每次调用 `income-forecast-2-0` 都自动生成新版，不能回退到旧 CSS 或旧交互。
7. 页面输出继续完全离线自包含，不新增 CDN、远程字体、前端框架或外部脚本。

## 3. 方案比较与选择

### 方案 A：只追加几条手机 CSS

优点是改动最少；缺点是只能修当前截图中的溢出，无法稳定覆盖地图、宽表、地市页、旧报告同步和未来生成。随着新报告字段变化，跑版会反复出现。

### 方案 B：模板优先的响应式报告工作台（采用）

在 Skill 模板中建立断点、容器、表格、地图和触控规则；生成器输出版本标记；发布管线把同一版 `styles.css` 和 `common.js` 同步到现有报告。桌面、平板、手机共享同一语义 HTML 和数据，仅通过 CSS/少量渐进增强改变呈现。

该方案一次解决当前体验和以后重复发布的兼容问题，维护成本最低。

### 方案 C：单独生成移动版报告

手机可获得完全定制的布局，但会形成两套模板、两套路由和两套测试，内容或权限很容易分叉，不适合高频自动发布。

## 4. 响应式结构

### 4.1 全局容器

- `html`、`body`、`.page-shell`、`.content`、所有 Grid/Flex 子项显式允许收缩；关键网格子项使用 `min-width: 0`。
- 页面宽度使用流体内边距和 `max-width`，兼容 `env(safe-area-inset-*)`。
- `overflow-x: clip` 只作为页面级最后防线，不能掩盖内容被截断；验收仍要求所有非表格内容的边界在视口内。
- 长词、长标题、路径和数值说明允许安全换行；业务表数字继续不换行并在局部滚动容器中展示。

### 4.2 断点

- `> 1024px`：桌面分析工作台。保留全省地图与侧栏双列、四列 KPI、地市页双列 Hero。
- `641–1024px`：平板两区布局。地图和统计上下分区，KPI 两列，信息卡片按内容形成一至两列。
- `<= 640px`：手机单列。页面间距收紧，标题缩放，导航工具条分行，KPI 首卡重点突出，其余紧凑排列。
- `<= 390px`：窄屏补偿。进一步压缩非信息性间距，保证 360px 下仍有 10px 以上页面边距和 44px 控件。

断点按内容需要而不是具体设备命名；横竖屏切换不需要重新加载页面。

## 5. 组件行为

### 5.1 顶部工具条

- 桌面继续一行显示品牌、数据日、日期选择、主题和打印。
- 平板允许自然换行，日期选择独占一行但不拉伸出屏幕。
- 手机保留“鄂”品牌标志和简短名称；地市页“返回全省”为清晰按钮；三个日期下拉形成等宽三列；主题和打印均保持可触达，不因屏幕窄而隐藏核心操作。
- Sticky Header 高度随内容变化，使用紧凑背景和底部细线；控件至少 44px 高。

### 5.2 Hero 与 KPI

- 手机端 Hero 减少空白，标题采用 `clamp()`，避免一屏只看到标题。
- KPI 保持全部指标。第一张“本月预估”作为主卡跨满宽度，其余卡片在可读条件下两列排列，360px 时必要时改单列。
- 数值使用 tabular numerals，单位和比较口径靠近数值，增长/风险色同时配合文字，不只依赖颜色。

### 5.3 湖北地图

- 桌面使用原 1000×650 SVG 视图和鼠标 Tooltip。
- 平板和手机使用响应式 `aspect-ratio`，不再用 480/620px 固定最小高度强撑首屏。
- SVG 始终 `max-width: 100%`；地图标签在窄屏适度减小但保持可读。
- 触屏点击地市直接进入详情；键盘 Focus 仍能显示信息。地图下方保留 17 地市可换行的文字入口，作为触控和无障碍备用路径。
- Tooltip 在触屏不成为访问数据的唯一方式，也不得超出地图容器。

### 5.4 图表和驱动因素

- 驱动条目在手机端使用“名称 + 数值”首行、条形图次行的两行结构，避免三列互相挤压。
- 趋势曲线卡改为单列；柱条允许压缩间距但保持当日强调。
- 对比条和多账期分摊条在窄屏允许标签换行，数值不被裁切。
- 机制流程在手机端垂直展示，箭头旋转为向下，并减少卡片内边距。

### 5.5 表格

- `.table-wrap` 永远不撑大父级；`.table-scroll` 承担横向滚动，设置 `overscroll-behavior-inline: contain` 和触控惯性。
- 手机端第一列使用 sticky 定位和与主题一致的实色/高不透明背景，滚动数值列时仍能识别业务或地市。
- 表格顶部显示短滚动提示和边缘渐隐，只有确实可滚动时由 `common.js` 增加状态类；滚动到末端后更新状态。
- 不把 7 列业务表压成无法阅读的小字，不删除列，不生成第二套卡片数据。

### 5.6 地市详情

- 地市 Hero、状态卡和指标改为手机单列；返回全省按钮始终可见。
- 17 地市导航在手机端成为可换行的紧凑 Chip 区，不形成整页横滚。
- 对比条、分摊条、驱动因素和业务表遵循与全省页相同的响应式规则。

## 6. 视觉系统

### 6.1 色彩和层级

- 背景使用更安静的深海军蓝渐变；面板分为普通、重点、风险三种表面层级。
- 青蓝只用于导航、关键轮廓和数据焦点；绿色、红色、琥珀继续承担语义色。
- 阴影从“大而黑”改为低透明度分层阴影；卡片边框更细，重点卡通过顶部光带或边线强调。
- 浅色主题同步定义表面、sticky 列背景和滚动渐隐，不能只反转背景。

### 6.2 字体和间距

- 继续使用系统字体栈，不下载字体。
- 标题、KPI、正文、说明建立稳定字号层级；正文和表格不因适配降到不可读尺寸。
- 桌面保持宽松，平板中等，手机紧凑；同层卡片的圆角、边框和内边距一致。

### 6.3 动效

- 只保留 hover/focus、主题切换和滚动提示等功能性过渡，时长 120–180ms。
- `prefers-reduced-motion: reduce` 时关闭平滑滚动和非必要过渡。
- 不增加粒子、自动轮播、视差或影响报告阅读的装饰动画。

## 7. 模板版本与 Skill 兼容

模板定义稳定常量 `INCOME_REPORT_UI_VERSION`，值采用可比较字符串，例如 `2026.08-responsive-1`。生成器把版本写入：

- `<meta name="income-report-ui-version" content="2026.08-responsive-1">`
- `body[data-ui-version="2026.08-responsive-1"]`
- `assets/report-meta.js` 的 `uiVersion`

`styles.css` 和 `common.js` 自身也携带同一版本标记。`create_report.py` 继续从模板复制这两个文件。原登录项目计划 Task 13 产生的 `sync_local_runtime()` 必须原子同步两项资源，并验证资源版本和校验和，不得只替换 `common.js`。同步目标包括本地权威报告目录和将要上传/部署的报告副本；同步不改旧报告的业务数据、主体 HTML 或路径。新生成页面使用 HTML/meta 三重标记；旧页面同步后以两项运行时资源标记作为升级凭据。

测试锁定以下行为：

1. 模板、生成 HTML 和 `report-meta.js` 版本一致。
2. 新生成报告带新版 CSS、JS 和版本标记。
3. 旧报告运行时同步后两项资源版本和校验和与模板一致；不要求改写旧页面业务 HTML。
4. 私有发布与公共部署都先同步、再验证、后上传；同步失败时安全失败，不发布混合版本。
5. 主 Skill 验证通过后再由原计划 Task 14 同步到移植副本和 ZIP。

## 8. 测试与验收

### 8.1 静态契约

- CSS 必须包含全局可收缩、表格局部滚动、sticky 首列、safe-area、`prefers-reduced-motion`、打印和 640/1024 断点规则。
- 生成器必须包含 UI 版本和表格滚动提示所需语义，不允许外部资产。
- `common.js` 只做渐进增强；脚本失败时表格本身仍可手动滚动、所有链接仍工作。

### 8.2 浏览器矩阵

对全省页和武汉地市页分别在 360×800、390×844、768×1024、1024×768、1440×900 执行：

- `document.documentElement.scrollWidth <= document.documentElement.clientWidth + 1`；
- 除 `.table-scroll` 外所有可见主内容边界位于视口；
- 表格在窄屏确实可局部横滚且 sticky 首列保持可见；
- 地图、KPI、日期、主题、打印、全省返回和地市入口可见可用；
- 可交互控件最小尺寸 44×44px；
- 360px 下正文计算字号不小于 13px；
- 深色、浅色、减少动效和打印样式均无关键内容丢失；
- 页面控制台无运行错误；favicon 404 不作为报告功能失败，但应在站点层补齐或明确忽略。

### 8.3 回归

- Skill 全量 Python 测试通过。
- 网站 Vitest、TypeScript 和 Playwright 全量测试通过。
- 用真实 `20260725` 报告完成跨设备截图与尺寸验证，并抽查一个私有日期走相同模板。

## 9. 风险与失败策略

- CSS `overflow-x: clip` 可能掩盖内容：浏览器测试逐元素检查边界，不只检查文档宽度。
- sticky 首列在透明背景下可能叠字：深浅主题分别使用明确背景 token。
- 旧报告 HTML 可能缺少新版语义：渐进增强只依赖现有 `.table-scroll` 等稳定结构；需要新增语义时由生成器和同步验证共同控制，不能静默半升级。
- 地图触屏无 hover：地市文字入口和直接点击路径保证功能可达。
- 未来 Skill 回退：UI 版本、资源校验和、同步顺序和测试共同形成发布门禁；检测到混合版本即停止发布。
