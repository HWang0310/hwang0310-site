# 收入预估密码认证与报告日期选择器设计

日期：2026-08-11  
状态：已确认

## 目标

1. 修复已登录成员使用正确当前密码时仍收到“当前密码错误”的问题。
2. 将登录后的完整报告长列表替换为年份、月份、日期三级联动选择器。
3. 保持零短信成本、同源访问、现有权限边界和双公共报告策略不变。

## 已确认根因

收入预估主页登录已改为：先用手机号查询 `profiles`，再使用该成员的已确认邮箱和密码调用 Supabase Auth。修改密码与重置密码后的重新登录仍直接把手机号传给 `signInWithPassword()`。

Supabase Auth 日志显示正常入口的 email provider 登录成功，而旧密码路径返回 `422 phone_provider_disabled`。因此当前密码并没有校验失败；失败发生在错误的认证身份路径上，随后被映射成了“当前密码错误”。

## 认证设计

### 统一身份参数

密码相关认证统一接收一个受信任的账号身份对象，至少包含：

- `userId`
- `email`
- `phone`
- `role`

服务端只使用来自已验证会话或服务端 `profiles` 查询的邮箱调用 Supabase email/password 登录。浏览器仍只提交手机号和密码，不接收或暴露邮箱。

### 修改密码流程

1. 校验同源 POST 和现有会话。
2. 解析当前密码与新密码。
3. 使用 `session.email + 当前密码` 重新认证。
4. 核对重新认证的 `userId` 与 `role` 必须与现有会话一致。
5. 更新密码与资料标记，撤销旧会话。
6. 使用 `session.email + 新密码` 建立新会话并设置新 Cookie。
7. 审计记录只保存稳定原因码，不记录手机号、邮箱或密码。

### 重置密码后的会话

邮箱重置链接验证成功后，从服务端读取受信任 profile。密码更新完成后，使用 `profile.email + 新密码` 建立会话，避免同类 phone provider 回归。

### 错误边界

- 凭据不正确仍返回“当前密码错误”。
- Supabase 5xx、响应不完整或身份不匹配返回通用服务错误。
- 不向客户端暴露 provider、邮箱、Auth 原始错误或身份是否存在。
- 密码更新状态不确定时继续清除旧 Cookie，保持当前安全策略。

## 完整报告日期选择器设计

### 页面结构

登录后的“完整报告归档”保留标题、在线报告数量和状态区，原报告卡片网格替换为：

- 年份下拉框
- 月份下拉框
- 日期下拉框
- 当前选择摘要（公开示例或权限报告、文件大小）
- “打开报告”主按钮

公开示例的两张卡片保持不变。

### 数据模型与联动

选择器完全由 `/projects/income-forecast/api/reports` 返回的在线、已授权报告生成，不写死日期：

1. 按日期降序整理报告。
2. 默认选中最新一期。
3. 年份变化时，月份自动切换到该年最新可用月份。
4. 月份变化时，日期自动切换到该月最新可用日期。
5. 日期变化只更新摘要与按钮目标，不自动跳转。
6. 点击“打开报告”后导航到 API 返回并通过现有路径校验的 `webPath`。

未来上传的新报告会自动出现在对应年月日，无需修改首页代码或模板。

### 响应式与无障碍

- 每个下拉框有可见标签和独立 `aria-label`。
- 控件与按钮最小高度 44px，支持键盘操作和清晰焦点。
- 桌面和平板横向排列；640px 以下纵向排列。
- 无报告时禁用选择器和按钮，并在 `aria-live` 状态区说明。
- 不使用选择即跳转，避免键盘和触屏误操作。

## 组件边界

- `functions/.../password/change.ts`：修改密码的认证编排。
- `functions/.../password/reset.ts`：重置后的会话建立。
- 共享密码认证助手：把受信任邮箱统一传给 Supabase，隔离 provider 选择。
- `src/income-forecast/client.ts`：报告分组、级联状态和导航。
- `projects/income-forecast/index.html`：语义化选择器容器。
- `src/income-forecast/styles.css`：响应式布局与状态样式。

## 测试与验收

### 自动测试

- 当前密码重新认证和新会话建立都使用受信任邮箱。
- 手机 provider 不再出现在修改密码与重置密码路径。
- userId/role 不匹配、错误当前密码和服务故障仍按既有安全边界处理。
- 日期分组、默认最新日期、年月级联和打开目标使用真实报告数据。
- 无报告状态、移动端布局、键盘标签与安全 `webPath` 均有回归覆盖。

### 生产验收

- 现有手机号仍可登录。
- 正确当前密码不再被误报；不在生产验收中擅自永久改变用户密码。
- 匿名仍只能访问 20260720、20260725。
- 登录后三级选择器展示全部授权在线日期，私有报告可正常打开。
- 360px、平板和桌面无横向溢出。
